# סוכן מסחר וירטואלי בקריפטו (Paper Trading)

> ⚠️ **דיסקליימר:** זהו כלי מחקר/הדגמה בלבד. כל הכסף כאן **וירטואלי** — אין חיבור
> לבורסת קריפטו אמיתית, ואף עסקה אמיתית לא מתבצעת. ההחלטות מבוססות על ניתוח של
> מודל שפה (Claude) ואינן ייעוץ השקעות ואינן ערובה לתוצאות. אין להשתמש בלוגיקה
> הזו למסחר בכסף אמיתי בלי בדיקה, אימות ופיקוח משמעותיים בהרבה.

## מה זה

סוכן שרץ **אוטומטית, פעם בשעה**, בודק מחירי קריפטו (BTC/ETH/SOL), מנתח את המצב,
ומחליט אם "לקנות"/"למכור"/"להחזיק" — עם כסף וירטואלי בלבד. כל החלטה, כולל
הנימוק שלה, נשמרת ומוצגת בדשבורד (`index.html`).

## מבנה הפרויקט

- `data/config.json` — פרמטרים: יתרת פתיחה, סל מטבעות, כללי סיכון. נקבע פעם
  אחת ידנית; הסוכן קורא אותו אבל לא משנה אותו.
- `data/portfolio.json` — המצב הנוכחי: מזומן, פוזיציות, היסטוריית שווי תיק.
- `data/decisions.json` — יומן מצטבר של כל החלטה (כולל כאלה שנדחו כי חרגו
  מכללי הסיכון).
- `scripts/` — סקריפטי Node.js ללא תלויות חיצוניות:
  - `fetch-prices.mjs` — שולף מחירים חיים מ-CoinGecko (API חינמי).
  - `apply-trade.mjs <buy|sell> <COIN> <usdAmount> "<reasoning>"` — מבצע עסקה,
    **אוכף בעצמו** את כללי הסיכון (חוסם ולא מבצע אם חורג), ושומר הכל.
  - `log-hold.mjs "<reasoning>"` — רושם החלטת "להחזיק" בלי לשנות את התיק.
- `index.html` / `style.css` / `app.js` — דשבורד סטטי (בלי build step) שמציג
  את התיק, גרף שווי לאורך זמן, פוזיציות, ויומן החלטות.

## עקרון העיצוב: הפרדה בין "מכני" ל"שיפוט"

הסקריפטים (קוד דטרמיניסטי) אחראים על החשבון הנכון של התיק ואכיפת כללי הסיכון.
ה-LLM לא כותב ישירות ל-JSON — הוא רק מחליט *מה* לעשות ומריץ את הסקריפט
המתאים; הסקריפט מסרב אם ההחלטה חורגת מהכללים שהוגדרו ב-`config.json`.

## כללי סיכון נוכחיים (`data/config.json`)

- יתרת פתיחה: $10,000 וירטואלי
- סל: BTC, ETH, SOL בלבד
- מקס' 20% מהתיק במטבע בודד
- רזרבת מזומן מינימלית: 10%
- ללא שורט, ללא לברג'

ניתן לערוך את `config.json` בכל עת כדי לשנות פרמטרים אלו.

## הרצה ידנית מקומית (לבדיקה)

```
node scripts/fetch-prices.mjs
node scripts/apply-trade.mjs buy BTC 500 "מומנטום חיובי חזק עם נפח מסחר גבוה"
node scripts/log-hold.mjs "אין סיגנל ברור כרגע, ממתין"
```

פתחו את `index.html` בדפדפן כדי לראות את הדשבורד עם הנתונים המקומיים.

## איך זה רץ אוטומטית

שגרה מתוזמנת בענן (Claude Code routine) מריצה מחזור ניתוח **פעם בשעה** —
המינימום שהפלטפורמה מאפשרת. בכל מחזור: שליפת מחירים → קריאת מצב התיק
והחלטות אחרונות → ניתוח → הפעלת `apply-trade.mjs` או `log-hold.mjs` בהתאם →
`git commit` + `push`. אם הדשבורד מתארח עם auto-deploy (GitHub Pages /
Vercel), הוא מתעדכן לבד בעקבות ה-push.

**ברירת המחדל האסטרטגית:** Hold. הסוכן פועל (קונה/מוכר) רק כשיש נימוק
משכנע — לא סוחר בכל מחזור רק כי הוא יכול.
