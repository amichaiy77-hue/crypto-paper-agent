# סוכן מסחר וירטואלי בקריפטו (Paper Trading)

> ⚠️ **דיסקליימר:** זהו כלי מחקר/הדגמה בלבד. כל הכסף כאן **וירטואלי** — אין חיבור
> לבורסת קריפטו אמיתית, ואף עסקה אמיתית לא מתבצעת. ההחלטות מבוססות על ניתוח של
> מודל שפה (Claude) ואינן ייעוץ השקעות ואינן ערובה לתוצאות. אין להשתמש בלוגיקה
> הזו למסחר בכסף אמיתי בלי בדיקה, אימות ופיקוח משמעותיים בהרבה.

## מה זה

סוכן שרץ **אוטומטית, פעם בשעה**, בודק מחירי קריפטו ומניות (BTC/ETH/SOL +
SNDK/SPCX/QQQ/CEG), מנתח את המצב, ומחליט אם "לקנות"/"למכור"/"להחזיק" — עם כסף
וירטואלי בלבד. תומך במינוף ובשורט (עד פי 10 חשיפה גולמית ביחס להון העצמי). כל
החלטה, כולל הנימוק שלה, נשמרת ומוצגת בדשבורד (`index.html`), ונשלחת גם
כהודעת Telegram אחרי כל מחזור.

## מבנה הפרויקט

- `data/config.json` — פרמטרים: יתרת פתיחה, סל מטבעות, כללי סיכון. נקבע פעם
  אחת ידנית; הסוכן קורא אותו אבל לא משנה אותו.
- `data/portfolio.json` — המצב הנוכחי: מזומן, פוזיציות, היסטוריית שווי תיק.
- `data/decisions.json` — יומן מצטבר של כל החלטה (כולל כאלה שנדחו כי חרגו
  מכללי הסיכון).
- `scripts/` — סקריפטי Node.js ללא תלויות חיצוניות:
  - `fetch-prices.mjs` — שולף מחירים חיים: קריפטו מ-CoinGecko, מניות מ-Yahoo
    Finance (שני מקורות חינמיים, בלי מפתח API).
  - `apply-trade.mjs <buy|sell> <SYMBOL> <usdAmount> "<reasoning>"` — מבצע
    עסקה, **אוכף בעצמו** את כללי הסיכון (מינוף/שורט, חוסם ולא מבצע אם חורג),
    ושומר הכל.
  - `log-hold.mjs "<reasoning>"` — רושם החלטת "להחזיק" בלי לשנות את התיק.
- `index.html` / `style.css` / `app.js` — דשבורד סטטי (בלי build step) שמציג
  את התיק, גרף שווי לאורך זמן, פוזיציות, ויומן החלטות.

## עקרון העיצוב: הפרדה בין "מכני" ל"שיפוט"

הסקריפטים (קוד דטרמיניסטי) אחראים על החשבון הנכון של התיק ואכיפת כללי הסיכון.
ה-LLM לא כותב ישירות ל-JSON — הוא רק מחליט *מה* לעשות ומריץ את הסקריפט
המתאים; הסקריפט מסרב אם ההחלטה חורגת מהכללים שהוגדרו ב-`config.json`.

## כללי סיכון נוכחיים (`data/config.json`)

- יתרת פתיחה: $10,000 וירטואלי
- סל: BTC, ETH, SOL, SNDK, SPCX, QQQ, CEG
- מינוף מותר, שורט מותר
- **אין** מגבלת אחוז לנכס בודד — המגבלה היחידה היא חשיפה גולמית כוללת
  (סכום |שווי כל הפוזיציות|) עד **פי 10** מההון העצמי של התיק
- אם ההון העצמי מגיע לאפס או שלילי, לא מתבצעות עסקאות ממונפות/שורט נוספות

ניתן לערוך את `config.json` בכל עת כדי לשנות פרמטרים אלו.

⚠️ מינוף פי 10 יכול לגרום לתנודות חדות מאוד בשווי התיק הוירטואלי — כולל
ירידה לאפס או שלילי תוך עסקה אחת. זה חלק מהניסוי (עדיין כסף וירטואלי בלבד).

## הרצה ידנית מקומית (לבדיקה)

```
node scripts/fetch-prices.mjs
node scripts/apply-trade.mjs buy BTC 500 "מומנטום חיובי חזק עם נפח מסחר גבוה"
node scripts/log-hold.mjs "אין סיגנל ברור כרגע, ממתין"
```

פתחו את `index.html` בדפדפן כדי לראות את הדשבורד עם הנתונים המקומיים.

## איך זה רץ אוטומטית

שתי שגרות מתוזמנות נפרדות בענן (Claude Code routines):

- **מחזור קריפטו** — כל כ-3 שעות, אבל לא בין 01:00–09:00 בלילה (שעון
  ישראל); הריצה הראשונה אחרי ההפסקה (בסביבות 09:00) מסכמת גם מה קרה בלילה.
- **מחזור מניות** — פעמיים ביום מסחר (ימי חול): בפתיחת המסחר האמריקאי
  (16:30) ובסגירתו (23:00), שעון ישראל. בודק גם אם פורסם דוח רבעוני
  טרי לאחד המניות ומשלב את זה בניתוח.

בכל מחזור: שליפת מחירים → קריאת מצב התיק והחלטות אחרונות → בדיקת בקשות
פתוחות להוספת נכס (ראו למטה) → ניתוח → הפעלת `apply-trade.mjs` או
`log-hold.mjs` בהתאם → `git commit` + `push` → הודעת Telegram. אם הדשבורד
מתארח עם auto-deploy (GitHub Pages), הוא מתעדכן לבד בעקבות ה-push.

**ברירת המחדל האסטרטגית:** Hold. הסוכן פועל (קונה/מוכר) רק כשיש נימוק
משכנע — לא סוחר בכל מחזור רק כי הוא יכול.

## הוספת נכס למעקב

בתחתית הדשבורד יש טופס קטן: מזינים סימול (למשל `DOGE` או `AAPL`) ובוחרים
קריפטו/מניה, ולוחצים "פתח בקשה בגיטהאב" — זה פותח issue מוכן-מראש בריפו.
בריצה הבאה של השגרה הרלוונטית (קריפטו או מניות), הסוכן קורא בקשות פתוחות,
מוסיף את הנכס ל-`config.json`, וסוגר את ה-issue. אין backend — כל המנגנון
עובד רק דרך git + issues.

## התראות Telegram

אחרי כל מחזור, הסוכן שולח הודעת סיכום ל-Telegram — אותו תוכן שנכנס ליומן
ההחלטות בדשבורד. הטוקן של הבוט **לא** נמצא בקוד הזה (הריפו ציבורי) — הוא
מוגדר רק בתוך הפרומפט של השגרה המתוזמנת עצמה, בצד השרת.
